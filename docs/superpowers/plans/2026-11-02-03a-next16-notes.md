## 1. Cache Components (`cacheComponents: true`)

### 1.1 What it changes
(03-api-reference/05-config/01-next-config-js/cacheComponents.md, 02-guides/migrating-to-cache-components.md, 01-getting-started/08-caching.md)
- Data fetching is **dynamic by default**. You opt IN to caching with `'use cache'`. Uncached async work (DB query, `fetch`) and request-time APIs (`cookies()`, `headers()`, `searchParams`, `params` not covered by generateStaticParams) run at request time.
- Next prerenders a **static shell** (Partial Prerendering is now the default model; `experimental.ppr` / `experimental_ppr` removed). Anything dynamic must sit under a `<Suspense>` fallback, or be cached.
- `fetch` is NOT cached by default; fetches inside a `'use cache'` scope are cached automatically. A Drizzle/postgres.js query is just "uncached async data" - it is only cached if wrapped in a `'use cache'` function.
- Requires Node.js runtime. `export const runtime = ...` is not supported with cacheComponents (remove it, incl. `'nodejs'`). (cacheComponents.md)
- `partialPrefetching: true` requires `cacheComponents`; unset => behaves `false` + warning; both become default in next major. (05-config/01-next-config-js/partialPrefetching.md)
- Client navigation keeps previous routes mounted but hidden via React `<Activity>` (state preserved, effects cleaned up on hide, recreated on show). Matters for our localStorage client components (favorites / compare): re-read storage in an effect that re-runs on show; use `useLayoutEffect` cleanup to reset transient UI. (cacheComponents.md "Navigation with Activity"; 02-guides/preserving-ui-state.md)
- Synchronous IO in the prerender (`new Date()`, `Date.now()`, `Math.random()`, `crypto.randomUUID()`) is a **build error** that cannot be opted out of; move it behind `<Suspense>` + `await connection()` (from `next/server`) or `await io()` (from `next/cache`), or into a `'use cache'` scope. (migrating-to-cache-components.md "Adopting incrementally" step 3; 03-api-reference/04-functions/io.md)
- Build-time requirement: anything inside `'use cache'` / the prerender runs during `next build`, so **`DATABASE_URL` and a reachable DB are needed at build time**. Also "data sources available at build-time prerender have to be available at request time too" (08-caching.md "Bots and crawlers"). A cache-fill that awaits runtime data hangs ~50s then errors: "Filling a cache during prerender timed out, likely because request-specific arguments such as params, searchParams, cookies() or uncached data were used inside "use cache"." (use-cache.md "Build Hangs")

### 1.2 Caching a DB-reading function for ~1 day
Imports: `import { cacheLife, cacheTag } from 'next/cache'` (both stable now; `unstable_cacheLife/unstable_cacheTag` names are gone: 02-guides/upgrading/version-16.md "cacheLife and cacheTag").
Directive string: `'use cache'` (variants: `'use cache: private'`, `'use cache: remote'`).

```ts
// src/lib/queries/schools.ts   (data fns: async, args serializable)
import { cacheLife, cacheTag } from 'next/cache'
import { db } from '@/db'

export async function getSchool(id: number) {
  'use cache'
  cacheLife('days')          // revalidate 1 day, expire 1 week, client stale 5 min
  cacheTag('schools', `school-${id}`)
  return db.query.schools.findFirst({ where: (s, { eq }) => eq(s.id, id) })
}
```
- Whole file: put `'use cache'` as the first statement; EVERY exported function must then be async (also `generateMetadata`/`generateStaticParams` if exported from that file). (use-cache.md "Caching a module's exports")
- `'use cache'` must be inside the function body (first statement) for function-level; functions/components must be `async`.
- `cacheLife` can only be called inside a cache scope, not at module scope; call it in the same function; call at most once per invocation (branches OK). Recommended to always set it explicitly (omitting => `default` profile). (cacheLife.md)
- Preset profiles (stale / revalidate / expire) (cacheLife.md table):
  | name | stale | revalidate | expire |
  | default | 5 min | 15 min | never |
  | seconds | 30 s | 1 s | 1 min |
  | minutes | 5 min | 1 min | 1 h |
  | hours | 5 min | 1 h | 1 day |
  | days | 5 min | 1 day | 1 week |
  | weeks | 5 min | 1 week | 30 days |
  | max | 5 min | 30 days | 1 year |
- Data changes weekly => `'days'` (~1 day) or `'weeks'`. Custom profile: `next.config.ts` `cacheLife: { weekly: { stale: 300, revalidate: 86400, expire: 60*60*24*14 } }` then `cacheLife('weekly')`; omitted keys inherit from `default`; `expire` must be > `revalidate`. Inline: `cacheLife({ stale: 300, revalidate: 86400, expire: 604800 })`. You may also redefine built-ins (incl. `default`) in config. Types for `cacheLife` names are generated by `next dev|build|typegen`.
- Short lifetimes: `revalidate: 0` or `expire < 5 min` => excluded from prerender (dynamic hole); `stale < 30 s` => excluded; `stale` 30 s-5 min => in prerender but not in App Shell. Only `seconds` hits these. Client router enforces min 30 s stale. (cacheLife.md "Prerendering behavior")
- Cache key = build ID + function ID + serialized args (+ captured closure vars). New deploy => all `use cache` entries start empty. (use-cache.md "Cache keys", "Runtime caching considerations")
- Storage: default in-memory LRU; persists across requests only when **self-hosted** (`next start`); on serverless entries may not persist. `cacheMaxMemorySize` configurable; `'use cache: remote'` + `cacheHandlers` for shared durable cache (network roundtrip, platform fees). (use-cache.md)
- Serialization: args must be serializable (primitives, plain objects, arrays, Date, Map, Set, typed arrays); NOT class instances, functions, symbols, URL. Return values may additionally be JSX. `bigint` not listed => not covered (convert in the query layer). So pass `number`/`string` args, never a `URLSearchParams`, `Request`, or Drizzle `db` object.
- Inside a cache scope you CANNOT read `cookies()`, `headers()`, `searchParams` (error `next-request-in-use-cache`, applies down the call stack; can pass `next build` and fail under `next start` for dynamically rendered routes). Read them outside, pass values as args. `React.cache` has an isolated scope inside `use cache`. (use-cache.md "Constraints")
- `cacheTag('a','b')` (string args), then invalidate: `updateTag('a')` (Server Actions only, read-your-writes) or `revalidateTag('a', 'max')` - **second argument (a cacheLife profile) is now required**; single-arg is deprecated/TS error. Also `refresh()` (`next/cache`, in Server Actions). (cacheTag.md; version-16.md "Caching APIs")
  For a weekly import job use a Route Handler calling `revalidateTag('schools', 'max')` (stale-while-revalidate) after the DB load.
- `unstable_cache` is superseded by `use cache` (still exists). `unstable_noStore` is legacy; `connection()` replaces it. (unstable_cache.md, unstable_noStore.md)
- Components can be cached too (`'use cache'` in an async component; props must be serializable; `children`/slots pass through untouched).

### 1.3 Route segment config under cacheComponents
(03-api-reference/03-file-conventions/02-route-segment-config/index.md, migrating-to-cache-components.md)
- `export const dynamic`, `revalidate`, `fetchCache`: **removed/error** with cacheComponents ("route segments that still export dynamic, revalidate, or fetchCache will error"). Replace: `force-dynamic` => delete; `force-static` => delete + `use cache` + `cacheLife`; `revalidate = N` => `cacheLife(...)`.
- `export const dynamicParams`: **not supported**; build fails: `Route segment config "dynamicParams" is not compatible with `nextConfig.cacheComponents`.` Unlisted params render on request; for "reject unknown" call `notFound()` when the id resolves to no row.
- `runtime` not allowed (see 1.1). `experimental_ppr` removed.
- Still available: `maxDuration`, `preferredRegion` (deprecated), and new (cacheComponents only) `export const instant = true | false | {level}` and `export const ensureStatic = 'auto'|'shell'|'prefetch'|'navigation'|false`, `export const prefetch`. `instant = false` opts a segment out of instant-navigation validation (does NOT clear sync-IO errors); codemod `npx @next/codemod@canary cache-components-instant-false ./src/app`. (route-segment-config/instant.md, ensureStatic.md)
- Route Handlers `GET`: no `dynamic='force-static'`; call a `'use cache'` helper (directive cannot be put on the `GET` export itself).

### 1.4 `searchParams` / `cookies()` / `headers()` and Suspense
(migrating-to-cache-components.md "cookies, headers, and searchParams"; 08-caching.md "Working with runtime APIs"; streaming.md L380)
- All are request-time. Accessing outside `<Suspense>` => "blocking-route" / "blocking-prerender-runtime" insight in the dev overlay (dev: 200 + overlay only) and **`next build` fails** with the "blocking route error" if the prerender finds no Suspense boundary above the dynamic access (links: docs/messages/blocking-prerender-dynamic, blocking-prerender-runtime). The **exact error message string is not covered** in the bundled docs (messages pages are not bundled).
- A `loading.tsx` high in the tree counts as a boundary but makes the whole segment's content the fallback; prefer inline `<Suspense>` close to the dynamic read. (streaming.md L380)
- Pattern: page is a sync (non-awaiting) component; pass the promise down; await inside Suspense:
```tsx
// src/app/[locale]/explore/page.tsx
import { Suspense } from 'react'
export default function ExplorePage(props: PageProps<'/[locale]/explore'>) {
  return (
    <>
      <h1>...static heading...</h1>
      <Suspense fallback={<ResultsSkeleton />}>
        <Results searchParams={props.searchParams} locale={...} />
      </Suspense>
    </>
  )
}
async function Results({ searchParams }: Pick<PageProps<'/[locale]/explore'>, 'searchParams'>) {
  const { q, region, field, control, minTuition, maxTuition, page } = await searchParams
  const rows = await searchSchools({ q: str(q), region: str(region), page: Number(str(page) ?? 1) }) // 'use cache' fn, primitive args
  ...
}
```
- Cached function receiving values extracted from searchParams: **allowed and recommended** ("Passing runtime values to cached functions", 08-caching.md). Each distinct arg set = its own cache entry (consider bounding/normalizing params, e.g. clamp `page`, whitelist enums, otherwise cache-key explosion from arbitrary `q`).
- With `<Link prefetch={true}>` the framework resolves `searchParams` from the link URL and includes the cached result in the prefetch (08-caching.md "Prefetching").
- `searchParams` is a plain object (not URLSearchParams); values `string | string[] | undefined`. Compare page `?ids=1,2,3`: same pattern, split/parse inside the Suspense child, pass number[] / string to cached fn.
- Cookie `region` read on the server => `await cookies()` inside a Suspense'd leaf, then pass the value into cached fns as an arg. Reading cookies in the root layout blocks every segment under it. Cookies can only be SET in Server Functions / Route Handlers (not during render); client `document.cookie` is fine for our client component. (functions/cookies.md; preventing-flash-before-hydration.md L298)
  Simplest for a static-friendly site: keep `region` purely client-side (cookie written by client component, applied as a default filter on client navigation) or read it in one small Suspense'd component.
- `'use cache: private'` exists for reading runtime data inside a cached scope (browser-only cache, request-time, excluded from static shell). Not needed for our use case. (directives/use-cache-private.md)
- `generateMetadata` follows the same rules. If it uses runtime data while the page is otherwise fully prerenderable => error; either `'use cache'` the metadata data fetch, or add a Suspense'd `<Connection/>` marker using `await connection()`. (04-functions/generate-metadata.md "With Cache Components")

### 1.5 `params` + `generateStaticParams` + `dynamicParams`
(04-functions/generate-static-params.md; file-conventions/dynamic-routes.md "With Cache Components"; migrating-to-cache-components.md; 02-guides/incremental-static-regeneration-cache-components.md)
- `params` is runtime data **unless** `generateStaticParams` supplies values. Without it: all params unknown at prerender => access to `params` must be inside `<Suspense>` (or `loading.tsx`); shell prerenders, content renders per request.
- With cacheComponents, `generateStaticParams` is **not mandatory** (removing it => route rendered on every request, no ISR even with `use cache` data). But if present it **must return at least one param**; `[]` => build error `empty-generate-static-params`. Placeholder trick `[{ id: '__placeholder__' }]` + `notFound()` is mentioned but discouraged.
- Unlisted ids are still served on demand: App Shell first, then upgraded with real params and stored in the ISR cache. Details: with `partialPrefetching: true` (our scaffold) you may `await params` inside `<Suspense>` and the fallback is served instantly for unlisted paths; without it, await `params` OUTSIDE any Suspense (incl. `loading.tsx`) to get a per-URL ISR entry. (ISR-with-CC guide)
- Build-time validation only runs against the sample params you return; branches not hit by samples aren't validated.
- Every dynamic segment needs values: for `/[locale]/schools/[id]` return both (`{locale:'zh', id:'1'}` ...) bottom-up, or per-layer (`[locale]` layout returns locales; child page returns ids using parent `params`). Child `generateStaticParams` runs once per parent param set. A segment can only generate params for itself and ancestors, not below.
- Root params: each root dynamic segment (our `[locale]` if root layout lives there) must have >= 1 value from generateStaticParams "or the build fails". (functions/next-root-params.md)
- Recommended shape (our case, DB changes weekly):
```ts
export async function generateStaticParams() {
  const rows = await getTopSchoolIds(50)           // 'use cache' fn, cacheLife('weeks')
  return locales.flatMap((locale) => rows.map((r) => ({ locale, id: String(r.id) })))
}
```
  params values are strings. `notFound()` for ids with no row.
- `dynamicParams` is NOT usable (see 1.3).
- Client hooks that read route (`usePathname`, `useParams`, `useSelectedLayoutSegment(s)`) suspend on routes with params not covered by generateStaticParams -> wrap leaf in `<Suspense>` or build fails. `useSearchParams` ALWAYS needs Suspense. (migrating-to-cache-components.md; functions/use-pathname.md "Cache Components")
- In layouts do NOT `await params` at the top level (blocks layout prerender); pass the promise down to the consumer inside Suspense. EXCEPTION is the root `<html lang>` (see 3.5).

## 2. `params` / `searchParams` types
(03-file-conventions/page.md; layout.md; 02-guides/upgrading/version-16.md "Async Request APIs")
- **Both are Promises.** Sync access fully removed in 16 (was a compat shim in 15). Same for `cookies()`, `headers()`, `draftMode()`, and `params` in `layout/page/route/default/opengraph-image/twitter-image/icon/apple-icon`; image fns also get `id` as Promise; `sitemap({ id })` id is a Promise<string>.
- Manual typing: `{ params: Promise<{ id: string }>; searchParams: Promise<{ [key: string]: string | string[] | undefined }> }`.
- Client Component pages may unwrap with React `use(searchParams)` (then needs Suspense).
- Global helpers (no import; generated by `next dev`, `next build`, or `npx next typegen`; also `RouteContext<'/api/x/[id]'>` for route handlers):
```tsx
export default async function Page(props: PageProps<'/[locale]/schools/[id]'>) {
  const { locale, id } = await props.params          // { locale: string; id: string }
  const sp = await props.searchParams                 // string | string[] | undefined values
}
export default function Layout(props: LayoutProps<'/[locale]'>) {  // props.children, props.params, named slots (@slot) typed
}
async function Child({ params }: Pick<PageProps<'/[locale]/schools/[id]'>, 'params'>) {}
```
  Literal route string gives strict keys; static routes => `params: {}`. Before types are generated (fresh clone / CI) run `npx next typegen` before `tsc` or the globals are missing. Types land in `.next/types` (tsconfig `include` has `.next/types/**/*.ts`, `.next/dev/types/**/*.ts`).
- `generateMetadata({ params, searchParams }, parent)`: same Promise props; can type first arg with `PageProps<'/route'>`.

## 3. Internationalization (02-guides/internationalization.md)

### 3.1 Official pattern (no library)
- Routing by sub-path: put ALL special files under `app/[lang]` (we use `[locale]`) so `lang` reaches every layout/page. Root layout may live in `app/[lang]/layout.tsx`.
- Guide uses `@formatjs/intl-localematcher` + `negotiator` to pick a locale from `Accept-Language`, in `proxy.js`. (Optional deps; for 2 locales a hand-rolled parse is fine.)
- Dictionaries: JSON per locale loaded via dynamic import:
```ts
// src/app/[locale]/dictionaries.ts
import 'server-only'
const dictionaries = {
  zh: () => import('./dictionaries/zh.json').then((m) => m.default),
  en: () => import('./dictionaries/en.json').then((m) => m.default),
}
export type Locale = keyof typeof dictionaries
export const hasLocale = (l: string): l is Locale => l in dictionaries
export const getDictionary = async (l: Locale) => dictionaries[l]()
```
```tsx
export default async function Page({ params }: PageProps<'/[locale]'>) {
  const { locale } = await params
  if (!hasLocale(locale)) notFound()          // import { notFound } from 'next/navigation'
  const dict = await getDictionary(locale)
}
```
  (`hasLocale` narrows `string` -> `Locale`; also gives 404 for `/foo/...`.)
- New in 16: `next/root-params` - `import { locale } from 'next/root-params'` gives an async getter for each dynamic segment ABOVE the root layout (name = folder name; must be a valid JS identifier, so `[locale]` ok, `[post-slug]` not). Works in Server Components and server utils; NOT in Client Components, Server Actions, Route Handlers. Removes prop-drilling `params`; in a `use cache` scope only the root params actually read join the cache key. No `server-only` needed in files importing it. (functions/next-root-params.md; guide "Sharing the locale across your app")
```ts
export const getDictionary = async () => { const l = await locale(); if (!hasLocale(l)) notFound(); return dictionaries[l]() }
```

### 3.2 `generateStaticParams` for locales
```tsx
// src/app/[locale]/layout.tsx  (root layout)
export async function generateStaticParams() { return [{ locale: 'zh' }, { locale: 'en' }] }
```
(Required to return >= 1 with cacheComponents; see 1.5.)

### 3.3 `<html lang>` with root layout under `[locale]`
```tsx
// official guide variant
export default async function RootLayout({ children, params }: LayoutProps<'/[locale]'>) {
  return <html lang={(await params).locale}><body>{children}</body></html>
}
// root-params variant
import { locale } from 'next/root-params'
export default async function RootLayout({ children }: LayoutProps<'/[locale]'>) {
  return <html lang={await locale()}><body>{children}</body></html>
}
```
Because locales are enumerated by `generateStaticParams`, the layout prerenders per locale. Do NOT derive `lang`/`dir` from cookies/headers in the root layout (would block the whole subtree); guide for that case = inline script (preventing-flash-before-hydration.md). The `lang` value is the raw URL string; validate with `hasLocale` somewhere (page) - an unlisted `/xx/...` still reaches the layout (no dynamicParams), so also `notFound()` in the layout or page when `!hasLocale`.
- The scaffold's `src/app/layout.tsx` + `src/app/page.tsx` must be MOVED under `src/app/[locale]/` (root layout cannot coexist with another root layout unless route groups are used). Keep `globals.css` import and font variables in the new root layout.

### 3.4 Redirect `/` -> `/zh` : `proxy` (formerly middleware)
(01-getting-started/16-proxy.md; 03-file-conventions/proxy.md; version-16.md "middleware to proxy")
- File: `proxy.ts` at project root, or `src/proxy.ts` if `src/` is used (same level as `app`). One file per project. `middleware.ts` is deprecated (still works) - rename file AND function.
- Export: `export function proxy(request: NextRequest)` (named) or `export default function proxy(...)`. May be `async`. Config: `export const config = { matcher: [...] }` (matcher values must be static constants/regex strings; must start with `/`).
- Runtime: **Node.js only** and not configurable; setting `runtime` in proxy throws; `edge` not supported in proxy. `fetch` cache options have no effect in proxy; not for slow data fetching.
- Without `matcher` it runs on EVERY request incl. `_next/static`, `_next/image`, `public/`. Use negative matching.
```ts
// src/proxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

const locales = ['zh', 'en'] as const
const defaultLocale = 'zh'

function pickLocale(req: NextRequest): string {
  const header = req.headers.get('accept-language') ?? ''
  for (const part of header.split(',')) {
    const tag = part.split(';')[0].trim().toLowerCase()
    const base = tag.split('-')[0]
    if ((locales as readonly string[]).includes(base)) return base
  }
  return defaultLocale
}

export function proxy(request: NextRequest) {
  const { pathname } = request.nextUrl
  const hasLocale = locales.some((l) => pathname === `/${l}` || pathname.startsWith(`/${l}/`))
  if (hasLocale) return
  request.nextUrl.pathname = `/${pickLocale(request)}${pathname === '/' ? '' : pathname}`
  return NextResponse.redirect(request.nextUrl)
}

export const config = {
  // skip api, _next/*, and any path containing a dot (files in public/)
  matcher: ['/((?!api|_next/static|_next/image|.*\\..*).*)'],
}
```
  Official guide matcher is `'/((?!_next).*)'`; docs' negative-match example: `'/((?!api|_next/static|_next/image|.*\\.png$).*)'` (proxy.md "Negative matching"). Option "only run on /": `matcher: ['/']`.
  Returning `undefined` (no return) = continue. `NextResponse.redirect` default status code: not stated in the pages I read -> not covered (pass explicit status as 2nd arg if you need one, e.g. 307/308 via `NextResponse.redirect(url, 308)`; verify in functions/next-response.md before relying).
- Simple alternative for a fixed `/` -> `/zh`: `redirects()` in `next.config.ts` (docs say prefer config redirects for simple cases, proxy for request-data logic). Cookie-remembered locale can be read via `request.cookies`.
- Proxy runs before render; our `/` has no page once everything is under `[locale]`, so the redirect is what serves `/`.

## 4. not-found and metadata

### 4.1 not-found
(04-functions/not-found.md; 03-file-conventions/not-found.md)
- `import { notFound } from 'next/navigation'`; `notFound()` throws (return type `never`, no `return` needed); works in Server Components, Server Functions, Route Handlers; injects `<meta name="robots" content="noindex">`. A `try/catch` around it swallows it (use `unstable_rethrow` from `next/navigation`).
- `app/[locale]/not-found.tsx` (default export component; may import `Link` from `next/link`) renders for `notFound()` in that segment tree. It is wrapped by that segment's `loading` Suspense and `error` boundary.
- **Status code**: 404 only if `notFound()` fires before streaming starts. If thrown inside a `<Suspense>` child after the shell is sent, status stays **200** (UI still shows not-found + noindex). For correct 404s on `/schools/[id]`: do `await params` + the existence check (cached query) at the page top level outside Suspense (works well because generateStaticParams/`use cache` is fast), then render the rest. Alternatively check in `proxy`. (loading.md "Status codes"; not-found.md)
- Unmatched URLs (no route at all, e.g. `/xx/foo` if layout lacks `hasLocale` check, or `/` w/o proxy) use the root not-found. With the root layout inside a top-level dynamic segment (`app/[locale]/layout.tsx`) the docs say composing a consistent global 404 is hard and point to **experimental** `global-not-found.js`: `next.config.ts` `experimental: { globalNotFound: true }` + `app/global-not-found.tsx` (must render its own `<html><body>`, import its own CSS/fonts; bypasses layouts). Marked experimental. (not-found.md "global-not-found.js (experimental)")
- `error.tsx` must be a Client Component (see error-handling doc 01-getting-started/10-error-handling.md; `catchError` fn exists in 04-functions/catchError.md) - not read in detail.

### 4.2 Metadata
(04-functions/generate-metadata.md)
```tsx
import type { Metadata, ResolvingMetadata } from 'next'
export async function generateMetadata(
  { params }: PageProps<'/[locale]/schools/[id]'>,
  parent: ResolvingMetadata,
): Promise<Metadata> {
  const { locale, id } = await params
  const school = await getSchool(Number(id))      // 'use cache' fn
  if (!school) notFound()
  return {
    title: school.name[locale], description: ...,
    metadataBase: new URL('https://example.edu'),   // needed for relative URLs
    alternates: {
      canonical: `/${locale}/schools/${id}`,
      languages: { 'zh-TW': `/zh/schools/${id}`, 'en': `/en/schools/${id}`, 'x-default': `/zh/schools/${id}` },
    },
  }
}
```
- Signature: `generateMetadata(props, parent)`; first arg `{ params, searchParams }` both Promises; `parent: ResolvingMetadata` optional; returns `Metadata | Promise<Metadata>`. Server Components only. Static alternative: `export const metadata: Metadata = {...}`.
- `alternates.languages` renders `<link rel="alternate" hreflang="..." href="...">`; also `alternates.canonical`, `.media`, `.types`. Relative hrefs are composed with `metadataBase` (`metadataBase: new URL('https://...')`, applies to current segment and below). Whether the literal key `'x-default'` is accepted: not shown in docs examples (examples use `'en-US'`, `'de-DE'`) -> not covered; types are in the Metadata `Types` section (L1048+).
- Metadata is **streamed** after initial UI for normal browsers (appended to `<body>`), but blocks in `<head>` for HTML-limited bots (UA sniff; `htmlLimitedBots` option overrides; `htmlLimitedBots: /.*/` disables streaming). Under cacheComponents: metadata that only reads cached data is part of the static shell; runtime-data metadata on an otherwise-static page raises an error (see 1.4).
- Same cache-key trick: `generateMetadata` and the page both call `getSchool(id)`; both hit the same `use cache` entry (dedupes DB read).

## 5. Links and navigation hooks
(02-components/link.md; 04-functions/use-router.md, use-search-params.md, use-pathname.md, use-params.md)
- Imports (client components, `'use client'`): `import { useRouter, usePathname, useSearchParams, useParams } from 'next/navigation'`. **Never** `next/router` in App Router. `import Link from 'next/link'` (Server Components OK).
- `Link` props (App Router): `href` (string|object, required), `replace`, `scroll`, `prefetch`, `onNavigate`, `transitionTypes` (16.2+). `as`, `shallow`, `locale` are Pages-Router-only props. Next 13+: no child `<a>`.
- `prefetch`: `"auto"`/`null` default, `true`, `false` (App Router `true` means FULL route prefetch, differs from Pages). With **`partialPrefetching: true`** the default `auto` prefetches only the per-route **App Shell** (not URL-specific data); `prefetch={true}` additionally resolves `params`/`searchParams`/URL and the cached content behind it (costs a server invocation per link). Prefetching only runs in production. Use `prefetch={true}` sparingly (e.g. explore->school card links) and `false` for long lists/compare toggles. (link.md `prefetch`; partialPrefetching.md; guides/optimizing-prefetching.md)
- `useSearchParams()` returns read-only `URLSearchParams`; **always wrap the component in `<Suspense>`** (search params are request-time). In prod builds a static page calling it without Suspense fails the build ("Missing Suspense boundary with useSearchParams", docs/messages/missing-suspense-with-csr-bailout). In dev it may appear to work without Suspense. Rule: client explore-filters/pagination controls read `useSearchParams` inside `<Suspense fallback>`. For updates: build a `new URLSearchParams(searchParams.toString())`, then `router.push(`${pathname}?${params}`)` / `replace`.
- `usePathname`/`useParams`: no Suspense needed when pathname fully known at prerender (static routes or covered by generateStaticParams); otherwise suspends -> wrap (e.g. a language switcher in a layout over a route with unlisted `[id]`). Push the hook into the smallest leaf.
- `useRouter()` (from `next/navigation`): `push`, `replace`, `refresh`, `prefetch`, `back`, `forward`; new `router.bfcacheId` (opaque key for Activity-preserved state). `useLinkStatus` has its own page (04-functions/use-link-status.md) - not read.
- Client components that touch `localStorage`/`document.cookie`: server HTML cannot know the value; initialising from storage during render => hydration mismatch. Docs approaches: lazy `useState` initializer for client-only trees / inline `<script>` before paint, `suppressHydrationWarning` on the element (02-guides/preventing-flash-before-hydration.md). Always `try/catch` storage access. Safe default: render the SSR/empty state, then read storage in `useEffect` (or `useSyncExternalStore` with a server snapshot) - not spelled out in these docs for the favorites case.

## 6. Environment variables and `server-only`
(02-guides/environment-variables.md; 01-getting-started/05-server-and-client-components.md "Preventing environment poisoning"; version-16.md "Runtime Configuration")
- `.env*` loaded into `process.env` automatically (order: `process.env`, `.env.$(NODE_ENV).local`, `.env.local` [skipped when NODE_ENV=test], `.env.$(NODE_ENV)`, `.env`). With `src/`, `.env*` files stay in the PROJECT ROOT, not in `src/`.
- Vars without `NEXT_PUBLIC_` are server-only. `NEXT_PUBLIC_*` are inlined at `next build` (frozen after build; dynamic `process.env[name]` lookups are not inlined).
- `DATABASE_URL`: server-only, never prefix with NEXT_PUBLIC. Build vs runtime: read in Server Components during dynamic rendering it is evaluated at request time; "To ensure env vars are read at runtime (not bundled/evaluated at build time) call `await connection()` first" (`import { connection } from 'next/server'`). BUT inside `'use cache'` / prerendered code, `process.env.DATABASE_URL` and the DB query execute at **build time**, so the DB must be reachable during `next build` (and again at runtime for revalidation / unlisted params). Create the postgres.js client lazily or at module scope reading `process.env.DATABASE_URL` (module scope is evaluated per server process; fine for self-hosted).
- `serverRuntimeConfig`/`publicRuntimeConfig` and `next/config` are **removed** in 16 - use env vars.
- Loading env outside Next (Vitest, drizzle-kit config): `import { loadEnvConfig } from '@next/env'; loadEnvConfig(process.cwd())` (package `@next/env`). `.env.test` is loaded when NODE_ENV=test, `.env.local` is not. (environment-variables.md)
- `server-only`: `import 'server-only'` at top of server-only modules (DB client, queries, `getDictionary`) makes a Client Component import fail at build with a clear message. Installing the npm package is **optional** - Next handles it internally and ships type declarations (install only if lint flags the extraneous import). `client-only` is the counterpart. Note: a Vitest unit test importing a file with `import 'server-only'` will throw outside Next unless aliased/mocked -> keep pure functions in files without it and DB query fns behind a thin `server-only` boundary, or add a Vitest alias for `server-only` (not covered in docs; project decision).
- `taint` API exists (`experimental.taint`, config/next-config-js/taint.md) - not needed.

## 7. Other breaking / notable vs Next 15
(02-guides/upgrading/version-16.md unless noted)
- Node.js >= 20.9, TypeScript >= 5.1 (docs table says 5.1.0), browsers Chrome/Edge/Firefox 111+, Safari 16.4+. React 19.2 (scaffold has react 19.3.0): View Transitions, `useEffectEvent`, `<Activity>`.
- **Turbopack is default** for `next dev` AND `next build` (no `--turbopack`). If a custom `webpack` config exists, `next build` FAILS (a plugin may inject one). Opt out: `next build --webpack` / `next dev --webpack`. `experimental.turbopack` => top-level `turbopack` option. Filesystem cache on by default (`experimental.turbopackFileSystemCacheForDev/ForBuild`; configure in config/next-config-js/turbopackFileSystemCache.md). `next dev` no longer shows `dev` in `process.argv` when loading config (use `NODE_ENV`/`phase`).
- `next lint` **removed**; `next build` no longer lints; `eslint` key in next.config removed. Use ESLint CLI directly (`"lint": "eslint"`, flat config `eslint.config.mjs` with `eslint-config-next/core-web-vitals` + `eslint-config-next/typescript` exactly as scaffold) or Biome. Codemod: `npx @next/codemod@canary next-lint-to-eslint-cli .`
- `middleware` -> `proxy` (see 3.4); config flags renamed (`skipMiddlewareUrlNormalize` -> `skipProxyUrlNormalize`). Codemod: `upgrade latest`.
- Async Request APIs fully async (section 2). `revalidateTag(tag, profile)` 2-arg; new `updateTag`, `refresh`; `cacheLife/cacheTag` stable names; `unstable_rootParams` removed -> `next/root-params`; `experimental.dynamicIO` / `experimental.useCache` removed -> top-level `cacheComponents`; PPR flag removed.
- **Tailwind with Turbopack**: scaffold uses `@tailwindcss/turbopack` (v4.3.3 in node_modules, "A Turbopack loader for Tailwind CSS v4"). Setup exactly as scaffold: devDeps `tailwindcss`, `@tailwindcss/turbopack`; `next.config.ts` `turbopack: { rules: { "*.css": { loaders: ["@tailwindcss/turbopack"], as: "*.css" } } }`; `globals.css` first line `@import "tailwindcss";` (+ `@theme inline {...}`); **no `postcss.config.*` file exists in the scaffold and none is needed for this path**. The bundled docs do NOT mention `@tailwindcss/turbopack` (grep: no hits); the documented path is `tailwindcss @tailwindcss/postcss` + `postcss.config.mjs` `{ plugins: { '@tailwindcss/postcss': {} } }` (01-getting-started/11-css.md). `turbopack.rules` mechanics (glob by file name unless it contains `/`; all matching rules run in order; `as` sets output type) are in config/next-config-js/turbopack.md. If anything runs with `--webpack`, the turbopack rule does nothing and you need the postcss route -> keep Turbopack.
- React Compiler: `reactCompiler: true` top-level (stable, **not enabled by default**; needs `babel-plugin-react-compiler` devDep; slower compile). Scaffold does not enable it.
- `next/image` defaults: `images.minimumCacheTTL` 60 s -> **4 h**; `imageSizes` no longer includes 16; `images.qualities` default `[75]` only (other `quality` coerced to nearest; direct `/_next/image?q=` unsupported => 400); `images.localPatterns.search` required for local src with query strings; `dangerouslyAllowLocalIP` default false; `maximumRedirects` default 3; `next/legacy/image` and `images.domains` deprecated (use `remotePatterns`). We likely only need plain `<Image>` for logos from remote hosts: configure `images.remotePatterns`.
- `fetch`: default is uncached (`auto no cache`: fetched once at build when prerendered; every request if request-time APIs detected). Caching is opt-in (`cache: 'force-cache'`, or inside `use cache`). With cacheComponents, don't use `next: { revalidate, tags }` - use cacheLife/cacheTag. (04-functions/fetch.md; migrating-to-cache-components.md "fetch cache options")
- `connection()` (`next/server`): `await connection()` marks following code request-time (replaces `unstable_noStore`). With cacheComponents prefer `io()` (`next/cache`) to exclude content from the static shell while still allowing cache/prefetch. A synchronous DB driver would need one of them; postgres.js is async so it is naturally "uncached async data".
- `unstable_` renames: `cacheLife`, `cacheTag` (above). `unstable_cache` replaced by `use cache`; `unstable_noStore` legacy; `unstable_rethrow` still `unstable_`.
- Removed: AMP, `serverRuntimeConfig`/`publicRuntimeConfig`, `devIndicators.{appIsrStatus,buildActivity,buildActivityPosition}`; `next build` output no longer prints `size`/`First Load JS`.
- Layout/prefetch overhaul: layout dedup + incremental prefetching; expect more but smaller prefetch requests.
- Dev-only "instant navigation" validation (insights in the dev overlay / MCP `get_errors`, not in HTTP responses). Optional: `@next/playwright` `instant()` helper for asserting instantly-visible UI; requires `exposeTestingApiInProductionBuild` (set `EXPOSE_TESTING_API=1` at `next build`) for prod-build tests. (guides/instant-navigation.md L376-393; testing/playwright.md)
- `AGENTS.md` block is rewritten by `next dev`; commit it or leave it.
- `npx next typegen` generates route types (`PageProps`, `LayoutProps`, `RouteContext`, `next/root-params` types) - run in CI before typecheck.

- **Limitation (verbatim gist): Vitest does not support `async` Server Components.** Unit-test only synchronous Server/Client components; use E2E for async components. Same advice in testing/index.md "Async Server Components".
- Pure functions + DB query functions: not specifically covered by docs. Notes for our plan: for node-only tests (queries) set `test.environment: 'node'` per file (`// @vitest-environment node`) since default config is jsdom; load env with `@next/env` `loadEnvConfig(process.cwd())` in a setup file; `'use cache'`/`cacheLife` calls will fail outside the Next runtime (calling `cacheLife` outside a cache scope throws) - so test the underlying query function separately from its cached wrapper (e.g. `queries.ts` pure/`server-only`-free and `cached.ts` wrapper with `'use cache'`). That structure is our design suggestion, not from docs.
### Playwright (testing/playwright.md)
- Install: `npm init playwright` (adds `playwright.config.ts`); example tests in `tests/*.spec.ts` (`import { test, expect } from '@playwright/test'`).
- Docs recommend running against production: `npm run build` then `npm run start`, then `npx playwright test`. Alternative: Playwright `webServer` option in `playwright.config.ts` (`command: 'npm run build && npm run start'`, `url`/`port: 3000`, `reuseExistingServer: !process.env.CI`) and `use: { baseURL: 'http://localhost:3000' }` so tests can `page.goto('/zh')`. Docs mention only `baseURL` and `webServer` generally (link to Playwright docs).
- CI: headless by default; `npx playwright install-deps`.
- Because `next build` prerenders with the real DB, CI needs `DATABASE_URL` for both build and start (docs: nothing specific; derived from section 1.1).

- Jest/Cypress guides also exist (testing/jest.md, cypress.md); not needed.

## 9. Minimal structure implied by the above
```
src/
  proxy.ts                         # '/' + locale-less paths -> /zh|/en
  app/
    [locale]/
      layout.tsx                   # ROOT layout: <html lang>, generateStaticParams -> locales, imports ../globals.css
      not-found.tsx
      page.tsx                     # home (static + cached data)
      explore/page.tsx             # sync page + <Suspense><Results searchParams=.../></Suspense>
      compare/page.tsx             # same pattern, ?ids=1,2,3
      schools/[id]/page.tsx        # generateStaticParams (>=1 per segment), await params, notFound(), cached queries
      programs/[id]/page.tsx
      dictionaries.ts + dictionaries/{zh,en}.json
    globals.css
  lib/queries/*.ts                 # async fns with 'use cache' + cacheLife('days'|'weeks') + cacheTag; args primitives only
  db/                              # drizzle + postgres.js, `import 'server-only'`
next.config.ts                     # keep cacheComponents, partialPrefetching, turbopack.rules; optional cacheLife custom profile
vitest.config.mts, playwright.config.ts
```
Gotchas to cite in the plan:
1. Remove any `dynamic`/`revalidate`/`dynamicParams`/`runtime` exports.
2. Each dynamic read (`searchParams`, `cookies()`, un-cached DB call) must be under `<Suspense>` or cached; otherwise `next build` fails with the blocking-route error.
3. `generateStaticParams` returning `[]` fails the build.
4. `revalidateTag` needs 2 args; `updateTag` only in Server Actions.
5. `notFound()` inside Suspense => HTTP 200; do the existence check before streaming for a real 404.
6. `useSearchParams` always needs Suspense; `usePathname`/`useParams` need it on routes with unlisted params.
7. DB must be reachable during `next build`.
